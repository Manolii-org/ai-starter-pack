# Optional model audit and source qualification candidate

This is an uninstalled source candidate. It changes no existing assessment worker,
required check, provider, credential, native merge rule or production gate. Model
assessment is optional audit under a future qualified replacement contract;
missing, failed, unavailable or credential-blocked model execution is never a
model PASS. The currently installed model/Judge requirements retain their actual
veto until an owning replacement has passed acceptance. Every result from this
candidate says `admission_authorized=false`.

## Deterministic reader and owner policy

Compile `config/source-qualification.json` from reviewed owner-local policy using
`schemas/source-qualification.schema.json`. The example is synthetic: its App and
publisher IDs, source hashes and Python-only scanner scope are not installed
policy. Record exact required names, numeric App identities, workflow paths and
complete workflow-file hashes, job/matrix artifact namespaces, actual required
recipe/scanner step names and numeric independent review publishers. Require
classification, meaningful deterministic execution and complete relevant security
execution. Missing, skipped, neutral or failed work is not successful evidence.
Adapt scanner inventory to every relevant language before adoption.

`qualify()` checks trusted normalized facts. Its local positive result describes
only that predicate; it does not authenticate the origin of local dictionaries
or grant an approval. The CLI accepts no local evidence file. Its read-only
collector fetches the native PR twice, requires independently selected exact
head/base and combined test source/tree, and loads the compiled policy from the
immutable base Git blob. It reads actual checks, attempts, jobs, complete source
metadata and owner-local artifacts using the existing authenticated read route.
A matching check name with another App is insufficient. Changed source, base,
workflow bytes, attempt, namespace or subject invalidates reuse. Malformed,
duplicate, nonfinite, oversized, denied or incomplete native facts hold rather
than taking an alternate credential route. Counted pagination requires a stable
typed total, unique native record IDs and a complete bounded page chain; unknown
or repeated review-thread cursors also hold.

The legacy role receipt composite records actual native job/check IDs and source
observations after an existing job. It runs no tests, models or deployment. It
observes clean physical tracked bytes and mode against the immutable combined
Git tree twice, rejects unsupported sources and ordinary untracked inputs, and
never opens ignored dependency or external symlink target bytes. Limits are
64 MiB per tracked file, 512 MiB total and 100,000 entries. This is repeated
observation, not an atomic snapshot. Security receipts require actual exit
outputs and raw complete Semgrep/Bandit reports, reviewed include/exclusion
inventories, no partial scans or scanner errors, and no findings. Warning-shaped
parse/timeout errors remain errors; timing profiles are not invented evidence.

## Native artifact origin boundary

GitHub's artifact API authenticates a workflow **run**, not the producing job.
Artifact metadata must match exact owner, run, head, name and size, and its ZIP
must contain only the bounded plain JSON member `source-qualification.json`.
Encoded symlink, FIFO, directory, device or socket kinds and DOS directory flags
hold. ZIP writers that omit POSIX kind bits remain byte-only JSON inputs; no
member is extracted and no native filesystem kind is invented. Native job
and check metadata must independently agree with the compiled workflow and
required successful steps. These checks establish coherence but cannot establish
job origin when another job in the same run executed untrusted PR code: it may
upload the reserved artifact name and forge every receipt field.

Therefore the current live collector never upgrades coherent role artifacts to
native source qualification. It emits `candidate_coherent=true`,
`source_qualified=false`, `native_transport_bound=false`, and
`cutover=held_native_component_artifact_origin_unqualified`, then exits nonzero.
The reusable candidate consequently remains held. Merely adding another reader
or copying these artifacts through a trusted wrapper cannot repair their origin.
Neither a matching payload job ID nor a local test is native job attestation.
A future owner-qualified complete verifier/producer route is required before a
live source-positive contract can replace existing checks.

## Exclusive metadata transport proof source

`source-qualification-producer-proof.yml` is a separate transport canary with
exactly one metadata-only job and no dispatch inputs. It never checks out,
executes, builds or tests PR code. It installs no packages with its token and has
only contents/actions/checks read permissions. A fixed reviewed step receives
the native token; no deployment, provider, model or OIDC credentials are used.
Other CI and untrusted execution must stay in different runs.

The controller reads only its compiled owner binding as data at
`github.workflow_sha`, then checks out the exact public component SHA selected
by that binding. Dispatch inputs cannot choose executable code. The retained
binding is `publication_status=pending`; its component/App IDs are unknown and
the workflow refuses them before executing component code. After normal reader
publication, an owning automatic compiler may record the reviewed immutable
component and verified App identity. `accepted_source_only` records source
publication only, never runtime qualification or execution authority. It is no
repo-variable enable ceremony and must not be treated as proof by itself.

`source_qualification_transport.py` re-fetches immutable owner binding/workflow
bytes at a required independent expected controller SHA. It requires the exact
native workflow, owner, event, controller head, typed attempt/run/check IDs,
verified App, complete attempt-specific job pagination and exactly one known
producer job. The reader requires the entire native attempt and job/check to
have completed successfully, then matches the sole artifact to the rederived
prepared subject/digest. An extra or skipped second job, unfinished run, different
controller, changed component, stale namespace or forged field refuses the proof.
The producer clears a stale output before validation and writes only in its
fixed no-follow native temporary namespace.

The seam accepts `workflow_dispatch` only. A `workflow_run` event's `head_sha`
can describe its trigger rather than its controller source; this reader never
substitutes it for a producer workflow revision. Controlled native proof must
verify the actual dispatch/source/attempt API semantics and protected namespace.
Unavailable semantics hold the seam. No API field is fabricated. A positive
canary means transport binding only and still reports `source_qualified=false`
and `admission_authorized=false`.

No active automatic dispatcher or owner caller is installed by this candidate.
After source publication and controlled native proof, integrate with the owner's
existing trusted publication/check events and bounded Git/CAS reconciliation;
no routine human dispatch, poller, service, database or signing system is added.
This explicit remaining adoption work must not be reported complete.

## Independent current-head review

The reader reuses `scripts/ci/review_evidence.py`. An authenticated exact-head
APPROVED review from a compiled existing publisher or its authenticated completed
summary recognizer may satisfy the review leg. An implementing author, empty
acknowledgement, unavailable edit provenance or unresolved thread cannot.
The public baseline has no Codex comment recognizer; such a comment remains
unsatisfied, not a fabricated approval.

All native review records require typed positive IDs and canonical duplicate
consistency before any source or disposition filter. Contradictory same-ID
records hold, including edits to a dismissed/commented/pending record; identical
snapshots remain idempotent. IDs never supply submission order.

All current-head reviews require an explicit recognized native state before
PENDING/COMMENTED/DISMISSED can be nondispositive. A dismissed record never
supplies approval or supersedes a separate still-active request. When the actual
requesting record has native state DISMISSED, that record itself is no longer a
request; no API dismissal is performed. Missing or unknown states hold. Effective
CHANGES_REQUESTED vetoes; no review is dismissed, cancelled or altered. Actual
`submitted_at`, normalized from timezone-bearing RFC3339 to UTC, orders opinions
from the same numeric reviewer. IDs identify records and never supply chronology.
Missing/malformed timestamps, unknown offsets and ambiguous latest equal-time
opinions hold. A strictly later native submission can supersede an earlier
opinion or timestamp tie; old-head requests remain audit while their unresolved
threads still block. No clock, created time or guessed API field fills a gap.

## Compatibility, validation and cutover

The original seven Pack owner recipes and all installed assessment/model check
surfaces remain unchanged. A separate credential-free deterministic recipe
checks this candidate and the retained old review parser. The existing Copier
Pack-only recipe filter excludes it from consumer profiles: its Pack test
environment and CI provenance are not an installed owner binding. Portable
helpers/schema still render normally. No new mandatory model
assessment is introduced. Portable readers, examples and schemas must be
published and pinned before any owner begins producing their evidence. Source
publication, native transport, complete source qualification and production
approval are distinct commitments.

Owner cutover requires actual complete positive/negative native canaries,
verified current identities/protection, full language/security coverage,
independent current-head review and accepted transport/provenance semantics.
Run alongside existing required contexts until the coordinated replacement is
accepted. Restore old requirements before rolling a replacement back. These
sources grant no human production decision, source readiness activation,
migration, feature activation or deployment. Detailed evidence stays owner-local.
Generic tests contain only synthetic Git/source/provider metadata. No cost or
invoice saving is measured by this uninstalled candidate.
